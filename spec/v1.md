## Purpose

This document freezes the SA-0 reference contract. It describes canonical bytes and exact field surfaces; it does not claim a production listener, filesystem, cache, installer, parser, or application bridge.

> A field absent from this document is rejected. Pair bearer `secret` is valid only on the Pair URL object and the Pair claim request. Receiver cache and merged views are never producer inputs.

## CanonicalJsonV1

| Property | Exact v1 rule |
|---|---|
| Encoding | UTF-8 without BOM or whitespace |
| Object keys | Strict UTF-8 byte order; duplicate and unknown typed fields rejected |
| Strings | NFC; shortest JSON escapes for `"`, `\\`, and U+0000–001F; other Unicode emitted directly |
| Numbers | Signed or unsigned canonical decimal integers only; no `+`, leading zero, `-0`, exponent, NaN, infinity, or float |
| Decode | Strict parse, typed decode, canonical re-encode, constant-time byte comparison |
| Public API | `CanonicalJsonV1::encode`, `decode`, and `decode_value` in `src/canonical.rs` |

## Wire and frame registry

| Registry | Value |
|---|---|
| Peer protocol | `1` |
| Report schema | `1` |
| State schema | `1` |
| Logical frame | `1` |
| Control | `1` |
| Consent scope | `usage.aggregate.read.v1` |
| Aggregation | `1` |
| TZDB | `2026c` |

Each Noise transport message is `u32be(ciphertextLen) || NoiseCiphertext`. The ciphertext maximum is 61,456 bytes. The authenticated plaintext frame has a 38-byte header and a 61,440-byte maximum.

```text
magic[4] = "SYR1"
frameVersion:u16be = 1
kind:u8 = 1 request | 2 response | 3 error
flags:u8 = bit0 final; all other bits zero
requestId[16]
chunkIndex:u32be
chunkCount:u32be
payloadLen:u32be <= 61,402
reserved:u16be = 0
payload[payloadLen]
```

| Kind | Count and ordering | Payload and logical cap |
|---|---|---|
| Request | One chunk; index 0; final set | 61,402 bytes |
| Error | One chunk; index 0; final set | 4,096 bytes |
| Response | 1–274 contiguous chunks; only last is final | 61,402 bytes per chunk; 16,777,216-byte logical body |

### Peer wire obligations

Every Pair claim, Pair status, Grant status and Peer error surface carries `protocol` equal to the Peer protocol `1`; any other value is `incompatible`. Pair status response (pending) `state` is `awaiting`, `rejected` or `expired`; Pair status response (approved) `state` is `approved`; Grant status response `state` is `active`, `revoked` or `expired`. `awaiting` is the wire name of the stored pending state `awaitingApproval`. Peer error `code` uses the control result-code numbering. The Pair claim request, Pair status request, Grant status request and Peer request field sets are pairwise distinct.

**Runtime obligations, not exercised by the SA-0 tests; enforced by `SA-2B2a` and `SA-2B2b` acceptance.** The value rules above, except pairwise distinctness of the four request field sets, and items (i)–(iii) below are runtime obligations. The SA-0 test `consent_surface_and_privacy_registry` asserts that its field sets equal the rows of the table above, that `secret` appears on no protocol surface except the Pair URL object and the Pair claim request, that the four peer request field sets are pairwise distinct, and that no peer surface carries `initiatorStatic`, `sasCode`, `sasGeneration` or `secretHash`.

- **(i) Identity binding.** Pairing payloads carry no identity field; the initiator identity comes only from the Noise remote static key. Pair status answers only when that key equals `pending.initiatorStatic`, and Grant status only when it equals `grant.initiatorStatic`; otherwise the answer is `unauthorized`, and its error payload is byte-identical to the one for an unknown ID (the frames differ only in the returned `requestId`). Any derivation of `pendingId` or `grantId` must mix in a value that an observer of the handshake cannot compute, because the Noise handshake hash is public. Response-time differences are outside this claim, because `offerId`, `pendingId` and `grantId` are 128-bit and, under that derivation rule, reach a peer only through the Pair URL or a successful response.
- **(ii) Secret confinement.** On the peer wire, `secret` may appear only in a transport-phase request frame, after the handshake completes, never in a Noise message 1 or 2 payload or in any response or error payload. Off the peer wire, `secret` exists only inside a Pair URL: in the control Offer-create response (`pairUrl`) and in the owner's hand-off of that URL to the receiver. Neither `secret` nor a Pair URL appears in any log.
- **(iii) Error codes.** The error `code` of Pair claim, Pair status and Grant status is one of 1 `invalid`, 2 `unauthorized`, 5 `busy`, 6 `incompatible` and 8 `internal`. On the peer wire, `unsafeState` is always reported as 8 `internal`. The peer report path additionally permits 3 `expired` and 4 `revoked`, and only after the static binding check has passed. That check (the Noise remote static equals `grant.initiatorStatic`) is an admission precondition evaluated before the authorization predicate of `spec/security-v1.md`; it is not a conjunct of that predicate and does not change it. A wrong secret, an unknown ID and a static mismatch produce byte-identical `unauthorized` error payloads.

### Control bodies and results

| Command ID | Name | Exact body | Success data |
|---:|---|---|---|
| 1 | `status` | `{}` | Status object from the surface table |
| 2 | `offerCreate` | `{ttlSeconds}` | Offer-create object from the surface table |
| 3 | `offerCancel` | `{offerId}` | `null` |
| 4 | `pendingList` | `{}` | Pending-list items sorted by `pendingId` |
| 5 | `approve` | `{pendingId,sasGeneration}` | `null` |
| 6 | `reject` | `{pendingId,sasGeneration}` | `null` |
| 7 | `revoke` | `{grantId}` | `null` |
| 8 | `listenConfigure` | `{bindHost,bindPort}` | `null` |
| 9 | `shutdown` | `{}` | `null` |
| 10 | `sharingSet` | `{enabled}` | `null` |
| 11 | `scopeApprove` | `{ownerInputsSha256}` | `null` |

Result `ok=0`; errors are `invalid=1`, `unauthorized=2`, `expired=3`, `revoked=4`, `busy=5`, `incompatible=6`, `unsafeState=7`, and `internal=8`. Error data is always `null`. `scanStatus` is `never`, `ok`, or `error`; `sourceFamilies` is sorted and unique with at most 128 entries. The `bindHost` and `nodeLabel` keys are always present. Each is `null` until configured, or a string: `bindHost` a canonical host, `nodeLabel` at most 128 bytes. `bindPort` is required and within 1024–65535 whether or not `bindHost` is set. `scopeApproved` is a required boolean. In `sharingSet`, `enabled` is a boolean. In `scopeApprove`, `ownerInputsSha256` is 64 lowercase hex characters (32 bytes): the owner-inputs digest of the scan scope the owner was shown (`spec/source-v1.md`); an agent whose current digest differs answers `invalid` and writes nothing (a runtime obligation of `SA-2C2b`, not exercised by the SA-0 tests). Command IDs outside 1–11 are refused.

### Pair URL

The canonical grammar is ASCII `syrtis://pair?offer=<lowercase-hex>`. Decoded hex is a CanonicalJsonV1 Pair URL object no larger than 4,096 bytes. Raw paste is capped at 16,384 bytes and the decoded URL at 8,192 bytes. Host accepts only canonical IPv4, canonical compressed IPv6, or lowercase LDH hostname. Port is 1024–65535 and expiry is in the next 1–900,000 milliseconds.

### Cache files

Each producer or receiver entry contains one CanonicalJsonV1 metadata object and one exact canonical response body. The filename is lowercase `SHA-256(cacheKeyJson)`. Producer and receiver roots cannot cross-read. Body hash validation precedes typed decode.
